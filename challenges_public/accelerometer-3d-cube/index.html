Challenge 2: Accelerometer 3D Cube

🎯 Medium Difficulty • 30 Points • All or Nothing

Challenge Overview

Transform the onboard ADXL345 accelerometer into a 3D input device! Read acceleration data on the FPGA, send it to the ESP32 over UART, and render a wireframe 3D cube on the OLED that rotates smoothly as you tilt the DE10-Lite board. This challenge combines embedded hardware interfacing with 3D graphics rendering.

Signal Flow:

  1. FPGA periodically reads X, Y, Z acceleration from ADXL345 via SPI
  2. FPGA sends raw 16-bit acceleration values to ESP32 over UART (9600 baud, JP1 header)
  3. ESP32 receives 6-byte acceleration packet (3 × 16-bit little-endian)
  4. ESP32 converts acceleration to pitch/roll angles
  5. 3D cube is rotated and rendered on 128×64 OLED display

UART Communication Protocol

Packet Format

The FPGA sends acceleration data as 6-byte packets, repeated at ~10 Hz minimum:

Byte 0: X acceleration (LSB, lower 8 bits) Byte 1: X acceleration (MSB, upper 8 bits) Byte 2: Y acceleration (LSB) Byte 3: Y acceleration (MSB) Byte 4: Z acceleration (LSB) Byte 5: Z acceleration (MSB) All values are signed 16-bit integers, little-endian.

Example decoding in C:

uint8_t packet[6]; // Read packet... int16_t accel_x = (int16_t)((packet[1] << 8) | packet[0]); int16_t accel_y = (int16_t)((packet[3] << 8) | packet[2]); int16_t accel_z = (int16_t)((packet[5] << 8) | packet[4]);

Implementation Steps

Step 1: FPGA ADXL345 SPI Interface

  1. Create SPI master controller in SystemVerilog
  2. Configure ADXL345 for:
    • ±16g range (DATA_FORMAT register)
    • Measurement mode enabled
    • Data rate ~100 Hz (POWER_CTL register)
  3. Read all 6 acceleration register bytes (0x32–0x37) in sequence
  4. Assemble into 16-bit X, Y, Z values

Step 2: FPGA UART Transmitter

  1. Create UART TX module (9600 baud, 8N1)
  2. Format acceleration data as 6-byte packet
  3. Send packet every ~100 ms (10 Hz minimum)
  4. Display packet count or status on 7-segment for debugging

Step 3: FPGA Top-Level Integration

  1. Instantiate SPI controller, UART transmitter, and support modules
  2. Create state machine: IDLE → READ_ACCEL → SEND_UART → WAIT → repeat
  3. Map JP1 header GPIO pins in .qsf constraints file
  4. Test: verify bitstream compiles and programs successfully

Step 4: ESP32 UART Reader

  1. Configure UART2 on ESP32 (RX=GPIO16, TX=GPIO17, 9600 baud)
  2. Implement packet reader: wait for 6-byte alignment, validate framing
  3. Parse bytes into signed 16-bit acceleration values
  4. Debug: print acceleration values to Serial Monitor

Step 5: ESP32 3D Cube Rendering

  1. Define 8 cube vertices in normalized coordinates (-1 to +1)
  2. Define 12 edges connecting vertices
  3. Implement pitch/roll rotation matrices:
    • Pitch (Y-axis): rotate around X
    • Roll (X-axis): rotate around Z
  4. Implement 3D-to-2D perspective projection
  5. Draw edges and vertices on OLED at 30+ Hz

Step 6: Acceleration-to-Angle Mapping

  1. Map raw acceleration (±32768) to angle range (±90°)
  2. Clamp angles to valid range
  3. Apply smoothing filter (optional: moving average) for stability

Step 7: Testing and Debugging

  1. Program FPGA bitstream
  2. Upload ESP32 firmware via PlatformIO
  3. Verify UART communication: use `pio device monitor` to check packets
  4. Verify 3D cube renders correctly
  5. Tilt board gently and observe cube rotation in real-time
  6. Check LED indicators on FPGA match tilt direction

Hints and Tips

FPGA Tips

  • Clock Dividers: Use clock dividers to generate SPI clock (~1 MHz) and UART clock from 50 MHz.
  • Register Reads: The ADXL345 supports multi-byte reads; read all 6 acceleration bytes in one SPI transaction for efficiency.
  • Data Format: Confirm the ADXL345 range (±16g) and output resolution (16-bit) in the datasheet.
  • Simulation: Use ModelSim to verify SPI timing and data reception before programming hardware.

ESP32 Tips

  • UART Buffer: Check `Serial2.available()` before reading to avoid race conditions.
  • Angle Mapping: Simple linear mapping from acceleration to angle works well for small tilts (< ±30°).
  • Cube Rotation Order: Apply rotations in a consistent order (e.g., pitch first, then roll) for predictable behavior.
  • Frame Rate: Aim for 30 FPS or higher for smooth visual rotation.
  • Filtering: A simple moving-average filter (5–10 samples) reduces noise and jitter.

Integration Tips

  • Framing: Without explicit packet markers, use timeout logic: if no byte arrives for > 1 second, resynchronize.
  • Wiring: Double-check GND connections between FPGA and ESP32; mismatched reference causes signal corruption.
  • Baud Rate: Both FPGA and ESP32 must use exactly 9600 baud. Off-by-one errors cause data loss.
  • Level Shifting: FPGA output is 3.3V; ESP32 RX is 3.3V tolerant. No level shifter needed.

Debugging Tools

  • FPGA: Use LEDs to show state (reading, transmitting, error). Display status on 7-segment.
  • ESP32: Use `Serial.printf()` to log acceleration values and angles in real-time.
  • UART Monitor: Use PlatformIO's `pio device monitor` to sniff raw UART traffic.
  • Oscilloscope: If available, probe UART RX/TX and SPI signals to verify timing.

Commonly Asked Questions

Q: What is the ADXL345 update rate?

A: Default is 100 Hz. You can program the POWER_CTL register to change it, but 100 Hz is sufficient.

Q: Do I need to calibrate the accelerometer?

A: Not for this challenge. The offset error is typically < ±50 mg and won't significantly affect visual rotation.

Q: Can I use I2C instead of SPI for the ADXL345?

A: Yes, if the board hardware supports it. SPI is usually faster and recommended.

Q: What if the cube appears inverted or rotated incorrectly?

A: Check the rotation matrix order and the projection. Pitch and roll must map to the correct axes.

Q: How do I handle UART packet loss?

A: Implement timeout logic: if no valid packet arrives within 1 second, resynchronize. Add a simple checksum or sync byte if needed.
